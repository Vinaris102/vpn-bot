# VPN Telegram-бот с оплатой по СБП/карте

## Состав проекта

- `app/bot.py` — Telegram-бот (aiogram), выбор тарифа, создание счёта
- `app/webhook_server.py` — FastAPI, принимает вебхуки об оплате от ЮKassa
- `app/scheduler.py` — фоновая проверка и отключение истёкших подписок
- `app/marzban_client.py` — интеграция с VPN-панелью Marzban
- `app/payment_client.py` — интеграция с ЮKassa (СБП + карта)
- `app/database.py` — модели БД (SQLite по умолчанию, легко заменить на PostgreSQL)
- `app/config.py` — настройки и тарифы (PLANS)
- `Dockerfile`, `docker-compose.yml` — контейнеризация для деплоя на VPS (см. раздел ниже)

Это три **независимых процесса**, которые работают параллельно и общаются через общую БД:
1. Бот (long polling)
2. Webhook-сервер (FastAPI, слушает уведомления об оплате)
3. Планировщик (отключает истёкшие подписки)

## Безопасность — что проверено и исправлено

Прогнан аудит по коду перед выкладкой на публичный сервер. Найдено и исправлено:

1. **Критично: вебхук ЮKassa не проверял подлинность запроса.** `app/webhook_server.py` раньше брал статус платежа прямо из тела входящего POST-запроса — то есть кто угодно мог отправить поддельный запрос напрямую на сервер и получить VPN без оплаты. Теперь статус всегда перепроверяется через официальный API ЮKassa (`get_payment_status`) вашим секретным ключом — тело вебхука используется только как триггер «проверь вот этот payment_id», а не как источник истины.
2. **Побочный баг**, найденный заодно: тот же файл передавал в Marzban «месяцы» вместо «дней» — не проявлялся на практике, так как ЮKassa ещё не подключена, но исправлен.
3. **Спам-защита в ручной оплате**: раньше можно было нажимать «Купить» много раз подряд, создавая заявку за заявкой и заваливая администраторов одинаковыми уведомлениями. Теперь при повторном нажатии на тот же тариф бот переиспользует уже существующую незакрытую заявку вместо создания новой.
4. **Ограничение длины «последних 4 цифр карты»** — раньше клиент мог прислать текст любой длины, который целиком уходил админам; теперь обрезается до 100 символов.
5. **`.gitignore` / `.dockerignore`** — добавлены, чтобы `.env` (токены, пароли) и файл БД (`*.db`) никогда не попали ни в git-репозиторий, ни в Docker-образ.

**Что нужно сделать вам вручную (не относится к коду):**
- Вы ранее присылали в этот чат настоящий токен бота и пароль администратора Marzban — если ещё не меняли, обязательно смените их сейчас (BotFather → Revoke token; смена пароля в самой Marzban-панели), прежде чем выкладывать бота на публичный сервер.
- На VPS держите открытыми наружу только реально нужные порты (`80`/`443` для nginx). Панель Marzban (`8000`) и вебхук бота (`8080`) не должны торчать в интернет напрямую — только через nginx с HTTPS, как уже настроено в `deploy/nginx.conf`.
- Файл `.env` должен иметь права `600` (`chmod 600 .env`) и никогда не публиковаться, не логироваться, не отправляться в чаты поддержки.
- Регулярно обновляйте зависимости (`pip list --outdated`) — особенно `aiogram`, `fastapi`, `httpx` — там иногда закрывают security-баги.

**Осознанное ограничение, а не баг:** бесплатный пробный период привязан к Telegram-аккаунту (`trial_used`), а не к устройству/IP — технически ничего не мешает завести много Telegram-аккаунтов ради повторных пробных периодов. Полная защита от этого потребовала бы верификации по номеру телефона или другого трения для пользователя — сознательно не делали, так как это ухудшило бы конверсию для честных клиентов.

## Docker — деплой на VPS

Три процесса бота (bot / webhook / scheduler) запускаются как отдельные контейнеры из одного образа — `Dockerfile` и `docker-compose.yml` в корне проекта.

### Первый запуск на сервере

```bash
# 1. Скопируйте проект на сервер (например через git clone или scp -r)
cd vpn-bot

# 2. Настройте .env (см. .env.example) — токен бота, Marzban, реквизиты карты
cp .env.example .env
nano .env
chmod 600 .env

# 3. Создайте папку для базы данных с правами на запись
mkdir -p data
chmod 777 data   # контейнер работает от непривилегированного пользователя,
                 # 777 на эту служебную папку — самый простой рабочий вариант
                 # для однопользовательского VPS; БД внутри неё видна только вам

# 4. Соберите образ и запустите все три контейнера
docker compose build
docker compose up -d

# 5. Проверьте логи
docker compose logs -f bot
```

Дальше в Telegram отправьте боту `/start` — должно заработать так же, как локально, но без тормозов Windows-машины.

### Перенос существующей базы (если тестировали локально и не хотите терять пользователей)

```bash
# на Windows-машине (там, где раньше крутился bot.py)
# скопируйте файл vpnbot.db на сервер, например через scp или WinSCP,
# в папку ./data на сервере (ту, что создали на шаге 3), назвав его vpnbot.db
```
Если базы ещё не было (свежий старт) — ничего переносить не нужно, таблицы создадутся автоматически при первом запуске.

### Обновление кода после изменений

```bash
git pull   # или скопируйте новые файлы на сервер
docker compose build
docker compose up -d   # пересоздаст контейнеры с новым образом, данные в ./data не тронет
```

### nginx и webhook — как раньше

`docker-compose.yml` публикует порт вебхука только на `127.0.0.1:8080` — снаружи его отдаёт nginx с HTTPS, конфиг тот же, что в `deploy/nginx.conf` (nginx в этой схеме продолжает жить на самом хосте, не в контейнере — так проще управлять сертификатами Let's Encrypt через `certbot`).

### Почему SQLite, а не PostgreSQL в Docker

Для одного VPS и текущей нагрузки SQLite в volume — рабочее и простое решение, не требует отдельного контейнера БД. Если позже трафик вырастет настолько, что понадобится PostgreSQL — это отдельная миграция (`DATABASE_URL` уже вынесен в конфиг именно для такой возможности).

## Деплой на сервер (продакшн)

В папке `deploy/` — всё для автоматического деплоя на чистый Ubuntu 22.04:

- `deploy.sh` — единый скрипт установки
- `vpnbot-bot.service`, `vpnbot-webhook.service`, `vpnbot-scheduler.service` — systemd unit-файлы (автозапуск, автоперезапуск при сбое)

### Пошагово

1. Купите домен и направьте A-запись на IP сервера (может быть отдельный сервер от VPN/Marzban)
2. Склонируйте проект на сервер и запустите от root:
   ```bash
   git clone <репозиторий> vpn-bot && cd vpn-bot
   sudo bash deploy/deploy.sh
   ```
3. Заполните `/opt/vpn-bot/.env` реальными значениями

## Команды администратора

Доступны только тем, чей `tg_id` указан в `.env` → `ADMIN_IDS` (через запятую, без пробелов). Все остальные пользователи эти команды просто не увидят (бот молча игнорирует).

| Команда | Что делает |
|---|---|
| `/admin` | Общая статистика: всего пользователей, активных подписок, оплат сегодня, общая выручка |
| `/users [страница]` | Список активных подписок, постранично (по 15) |
| `/find <tg_id>` | Карточка пользователя: статус, дата окончания, последние 5 платежей |
| `/payments [N]` | Последние N платежей по всем пользователям (по умолчанию 10) |
| `/grant <tg_id> <мес>` | Вручную выдать/продлить подписку — например, если кто-то перевёл деньги напрямую вам на карту, а не через ЮKassa. Автоматически создаёт/продлевает доступ в Marzban и присылает пользователю ссылку |
| `/revoke <tg_id>` | Вручную отключить доступ (бан, возврат денег и т.п.) |

Логика — в `app/admin.py`, подключена в `app/bot.py` как отдельный router.

**Важно:** узнать свой `tg_id` можно у бота @userinfobot в Telegram.

## Как сейчас устроена оплата (без эквайринга)

Пока вы не подключили ЮKassa и не оформили самозанятость — оплата идёт **вручную через карту**, с подтверждением администратором прямо в Telegram:

1. Пользователь выбирает тариф → бот показывает номер карты и просит перевести деньги
2. Пользователь присылает **скриншот перевода** или **последние 4 цифры карты**
3. Заявка автоматически уходит всем админам (из `ADMIN_IDS`) с кнопками **✅ Подтвердить** / **❌ Отклонить**
4. При нажатии «Подтвердить» бот **автоматически** создаёт/продлевает доступ в Marzban и присылает пользователю ссылку — вручную ничего в Marzban делать не нужно
5. Все заявки видно через `/payments` в админке, статус — `pending` / `succeeded` / `rejected`

Реквизиты карты задаются в `.env`:
```
CARD_NUMBER=2202 2083 0000 0000
CARD_HOLDER=Имя Фамилия
```

**Важно про автоматическое отслеживание переводов:** без банковского API (доступен обычно только ИП/юрлицам с эквайрингом) невозможно технически узнать о переводе на личную карту автоматически — банки не дают такой доступ физлицам. Поэтому вариант с ручным подтверждением через кнопку — самый рабочий полу-автоматический способ на сегодня. Когда оформите самозанятость и подключите ЮKassa (код уже есть в `app/payment_client.py` и `app/webhook_server.py`), процесс станет полностью автоматическим — переключение делается в `app/bot.py`, заменой блока показа реквизитов карты обратно на `create_payment(...)`.

## Пробный период (3 дня бесплатно)

При /start пользователю, который ещё не пробовал, показывается кнопка **«🎁 Попробовать 3 дня бесплатно»** — активируется мгновенно, без всякого подтверждения оплаты. Использовать можно только один раз (флаг `trial_used` в БД). Срок задаётся в `app/config.py` → `TRIAL_DAYS`.

## Доставка ссылки клиенту

После любой активации клиенту автоматически приходит QR-код подписки картинкой и сама ссылка текстом. Инструкция по подключению (iOS — Streisand, Android — v2rayNG) добавляется избирательно:

- **При первой выдаче** (пробный период, подтверждение оплаты, `/grant`) — инструкция идёт вместе со ссылкой, клиент подключается впервые и она нужна
- **При пересоздании уже существующей ссылки** (кнопка «🔄 Пересоздать ссылку» в профиле клиента, `/relink` у администратора) — инструкция **не** отправляется повторно, клиент уже знает, как добавлять конфиг, повторная инструкция только захламляет чат

Управляется параметром `include_instructions` в `deliver_subscription_link()` (`app/delivery.py`).

Если доставка не удалась (например, пользователь заблокировал бота), администратор увидит предупреждение с текстом ссылки в ответ на свою команду/нажатие — ошибка больше не проглатывается молча.

## Напоминание об истечении подписки

Отдельная задача в `app/scheduler.py` (`send_expiry_reminders`, запускается вместе с проверкой истёкших подписок раз в час) присылает клиенту сообщение за `EXPIRY_REMINDER_DAYS` дней (по умолчанию 3, настраивается в `app/config.py`) до конца подписки, с кнопкой **💳 Продлить**, которая сразу открывает список тарифов.

Напоминание отправляется **один раз на каждый период подписки** — отслеживается через `User.expiry_reminder_sent_for` (туда записывается та дата окончания, на которую уже напомнили). Если клиент продлевает подписку, `subscription_end` меняется — и напоминание сможет прийти снова перед следующим окончанием.

## Тарифы

Заданы списком в `app/config.py` (`PLANS`) — сейчас 4 тарифа: 1 мес (150₽), 3 мес (390₽), 6 мес (690₽), 12 мес (1190₽). У каждого тарифа есть `devices` — сколько устройств может использовать ссылку одновременно (сейчас у всех `1`; поле оставлено на будущее, если понадобится другой тариф с явным упором на несколько устройств).

Добавить свой тариф — просто добавьте элемент в список `PLANS`:
```python
{"code": "6m_promo", "months": 6, "price": 590, "label": "6 месяцев (акция)", "devices": 1},
```
`code` должен быть уникальным — используется в callback_data кнопки.

## Тизер реферальной программы после первой активации

Сразу после того, как клиент первый раз получает доступ (пробный период или первая подтверждённая оплата), следом приходит отдельное короткое сообщение с напоминанием о реферальной программе и личной ссылкой — момент, когда клиент уже доволен и наиболее склонен поделиться. Показывается **один раз на клиента** (флаг `User.referral_teaser_shown`), при последующих продлениях не повторяется, чтобы не надоедать.

Логика — в `app/referral.py`: `mark_referral_teaser_shown()` помечает флаг (внутри той же транзакции, что и активация), `send_referral_teaser_message()` отправляет само сообщение — разделены специально, чтобы тизер приходил **после** сообщения со ссылкой на подписку, а не до него.

## Исправление "query is too old" при подтверждении оплаты

Если между нажатием кнопки «Подтвердить»/«Отклонить» у администратора и ответом Telegram проходит больше ~15 секунд (например, Marzban на VPS отвечает медленно), сам callback "протухает" и финальный `callback.answer()` падает с ошибкой `Bad Request: query is too old`. Исправлено — теперь бот подтверждает нажатие кнопки **сразу**, а уже потом делает все запросы к Marzban; результат сообщается отдельным сообщением, а не через повторный `callback.answer()`.

## Устойчивость к рассинхрону БД ↔ Marzban

Если пользователя удалили вручную из панели Marzban (например, во время тестов), а в БД бота он всё ещё числится активным — раньше это приводило к ошибке `404 Not Found` при попытке продления. Теперь `activate_subscription_days` (см. `app/subscriptions.py`) сначала проверяет, существует ли пользователь в Marzban реально, и если нет — создаёт заново вместо продления.

При `/start` клиент получает персональное приветствие по имени (берётся из его Telegram-профиля) и постоянную кнопочную клавиатуру — без лишних служебных заголовков вроде «Главное меню»:

```
👋 Привет, Иван!

🎁 Вам доступен бесплатный пробный период на 3 дня.

Выберите действие:
```
(строка про пробный период показывается, только если он ещё не использован)

Вся навигация идёт через **постоянную клавиатуру снизу экрана** (см. следующий раздел) и системное меню команд (значок ☰) — отдельного инлайн-экрана «Главное меню» больше нет. Разделы ниже открываются кнопками клавиатуры или slash-командами:

- **🎁 Попробовать N дней бесплатно** — показывается, только если пробный период ещё не использован
- **💳 Купить подписку** — открывает список тарифов (1 мес — 150₽, 3 мес — 390₽, 6 мес — 690₽, 12 мес — 1190₽ из `PLANS` в `app/config.py`), с кнопкой «✖️ Закрыть»
- **👤 Мой профиль** — показывает статус, дату окончания, использованный трафик (из Marzban) и **всегда доступную ссылку на подключение** — если клиент потерял ссылку, он в любой момент зайдёт в профиль и получит её заново. Там же кнопка «🔄 Пересоздать ссылку», если старая не открывается
- **🤝 Пригласить друга** — реферальная ссылка и статистика приглашений
- **❓ Помощь** — инструкция по подключению (iOS → Streisand, Android → v2rayNG) + подсказка, что делать, если ссылка не пришла

Каждый из этих разделов открывается отдельным сообщением с кнопкой **«✖️ Закрыть»** — она просто удаляет это сообщение (а не возвращает к приветствию, как было раньше), потому что все действия и так всегда доступны через клавиатуру снизу. Логика — в `app/bot.py`, callback-хендлеры `menu:*`.

## Постоянное меню команд (значок ☰ / «/» рядом с полем ввода)

Кроме кнопок внутри чата, у бота настроено системное меню Telegram — то самое, что раскрывается по квадратику слева от поля ввода сообщения. Там продублированы все основные действия как slash-команды, чтобы клиент мог не искать кнопки, а просто нажать на нужный пункт:

- `/start` — 🏠 Главное меню
- `/trial` — 🎁 Попробовать бесплатно
- `/buy` — 💳 Купить подписку
- `/profile` — 👤 Мой профиль
- `/invite` — 🤝 Пригласить друга
- `/help` — ❓ Помощь

Регистрируется автоматически при каждом запуске бота (`bot.set_my_commands(...)` в `app/bot.py`) — ничего вручную настраивать в @BotFather не нужно. Меню в клиенте Telegram может обновиться не мгновенно (иногда нужно закрыть и открыть чат с ботом заново).

## Постоянная кнопочная клавиатура (иконка ⌨️ справа от поля ввода)

Отдельно от системного меню — ещё и постоянная клавиатура с крупными кнопками, всегда видна внизу экрана под полем ввода (не нужно ничего открывать, кнопки уже на виду):

```
[ 🎁 Попробовать 3 дня бесплатно ]
[ 💳 Купить подписку ] [ 👤 Мой профиль ]
[      🤝 Пригласить друга       ]
[         ❓ Помощь         ]
```

Присылается вместе с персональным приветствием при `/start`. Если клиент случайно скроет клавиатуру (нажав на иконку ⌨️ справа от поля ввода), она вернётся при следующем `/start`.

Логика в `app/bot.py`: `persistent_keyboard()` для самой клавиатуры, обработчики `kb_trial` / `kb_buy` / `kb_profile` / `kb_referral` / `kb_help` — те же действия, что и одноимённые slash-команды и inline-кнопки, просто ещё один способ дотянуться до того же самого. Эти обработчики зарегистрированы раньше состояния приёма скриншота оплаты, поэтому кнопки меню работают, даже если клиент завис на шаге отправки чека.

## Описание бота в @BotFather

Отдельно от кода — само описание бота (то, что видно в профиле бота и до первого /start) настраивается через @BotFather → `/setdescription`. Это не связано с кодом бота и настраивается один раз вручную, менять в коде для этого ничего не нужно.


## Реферальная программа

Каждый пользователь получает свою личную ссылку вида:
```
https://t.me/ваш_бот?start=123456789
```
где `123456789` — его `tg_id`. Когда друг переходит по этой ссылке, бот распознаёт параметр из `/start 123456789` и запоминает, кто кого пригласил (`User.referred_by_id`).

**Бонус начисляется только после того, как приглашённый друг реально оплатит первую подписку** (через обычный флоу ручной оплаты картой, подтверждённый администратором) — это защита от накрутки фейковыми регистрациями. Бонус — `REFERRAL_BONUS_DAYS` дней VPN (по умолчанию 14, настраивается в `app/config.py`), начисляется рефереру автоматически, вместе с уведомлением в Telegram.

Посмотреть свою ссылку и статистику (сколько друзей приглашено, сколько из них оплатили) можно через кнопку **🤝 Пригласить друга** в любом из меню, или командой `/invite`.

Вся логика — в `app/referral.py` (`maybe_reward_referrer`), вызывается из `app/admin.py` внутри подтверждения оплаты (`confirm_payment`), в той же транзакции, что и активация подписки — если начисление бонуса вдруг упадёт с ошибкой, это не блокирует выдачу основной подписки клиенту (ошибка просто логируется).

**Важно:** бонус НЕ начисляется через `/grant` (ручная выдача администратором без реальной оплаты через бота) — только через обычный флоу «оплатил → администратор подтвердил». Это осознанное ограничение, чтобы не путать ручные корректировки с органическими покупками.

## Что делать, если ссылка на подписку перестала открываться

Такое бывает — например, приложение "залипло" на старом конфиге, или ссылку случайно кто-то ещё получил. Есть два способа пересоздать её (старая при этом гарантированно перестаёт работать, срок действия и лимиты не меняются):

- **Пользователь сам:** в главном меню → «👤 Мой профиль» → «🔄 Пересоздать ссылку»
- **Админ за пользователя:** `/relink <tg_id>` — бот пересоздаст ссылку и сразу пришлёт её пользователю

Технически это вызов `POST /api/user/{username}/revoke_sub` в Marzban — он меняет UUID подписки, все старые сохранённые конфиги в приложениях перестают обновляться, нужно заново импортировать новую ссылку.

## Обновление БД после этого изменения (пробный период + надёжная доставка)

Если бот у вас уже запускался раньше и есть файл `vpnbot.db` — накатите миграцию (она безопасна, ничего не удаляет):

Также не забудьте поставить новую зависимость:
```bash
pip install -r requirements.txt
```
